## Findings by defect class
1. **Dead gate — literal `TRUE`** ×1: **REQ-21** (§2, `warn`) `condition = "TRUE"`. No reachable-fail.
   → `dp-iso14046-req21-true-gate`.
2. **Dead gate — enum-domain tautology** ×1: **REQ-01** (§5.1, `block`)
   `study_type IN {water_footprint_assessment, water_footprint_inventory_study}`; the IN-set = the
   entire enum domain → always true → no reachable-fail. → `dp-iso14046-req01-enum-tautology`.
3. **Greedy-OR escape-hatch** ×2: **REQ-18** `report_type == internal OR third_party_report == true`
   (internal report always passes; §6.2 a)–g) content unenforced) — weak. **REQ-20**
   `comparative_assertion_public == false OR critical_review_performed == true` — OR is *sound* per
   §7.1 (review only mandated for public comparative assertions). → `dp-iso14046-greedy-or-gates`.
4. **Cross-sheet gate** ×3: REQ-18 (reads `report_type`, owned WS-02), REQ-19 & REQ-20 (read
   `comparative_assertion_public`, owned WS-02). Symbols carry `consumer_worksheets`, but a
   strictly worksheet-local evaluator may resolve "fehlend" until WS-02 saved. →
   `dp-iso14046-crosssheet-gates` (same open question as A138 engine-output materialization).
5. **#22 hand-enterable-derived** ×1: **EQ-01** output `category_indicator_result` is
   `data_type=number`, UI-enterable, equation-produced; input `lci_result` likewise. →
   `dp-iso14046-eq01-enterable`.
6. **`IS NOT NULL` presence-only gate** ×5: REQ-06, REQ-11, REQ-15, REQ-19, REQ-22 — near-
   tautological on required boolean/enum fields (weak enforcement, not value gates). Note REQ-11
   *should* assert `allocation_balance_preserved == true`, not merely NOT NULL. →
   `dp-iso14046-isnotnull-gates`.
7. **Missing-doc value dependency** ×1 chain: `characterization_factor` / `category_indicator_result`
   draw CF values from an **out-of-library water-footprint LCIA method** (AWARE/WULCA-class); ISO
   14046 prints no CFs (§5.4.2 requires selecting a method). Formula VA-quotable, input value NR
   (formula-VA / input-NR split, cf. ISO-14067 EQ-01 / IPCC GWP). → `doc-lcia-water-method`,
   `dp-iso14046-lcia-method-source`.
8. **Presence/text-emptiness completeness gates** (class, not individually flagged): REQ-03/04/05/07/
   10/12/16 use `<field> != ''` string-emptiness. Correct pattern for a report standard, but they are
   presence gates not value gates. REQ-08/REQ-13/REQ-14 are genuine value gates (boolean-true / OR)
   and are sound.
9. **No printed normative table** (meta): ISO 14046 ships zero numeric threshold tables (only
   illustrative Figuras 1–5) → 0 `table` nodes is correct; recorded so re-audit does not flag a gap.

## Tier
**fix-first** — the encoding is structurally sound and mostly VA/VC-reachable, but two hard dead
gates (REQ-21 `TRUE`, REQ-01 enum-domain tautology) plus the REQ-18 greedy-OR escape-hatch and the
cross-sheet-gate resolution question must be fixed/ruled before a harness run is meaningful. Not
acquisition-blocked: the only NR chain (LCIA characterization factors) is a *value* dependency on an
out-of-library method — it caps EQ-01's numeric output at NR but does not block the 21 process/report
gates, which are the bulk of the standard's enforcement surface.
