## 4. Derived values + inheritance
Equations (3): EQ-01 `net_recovered_energy_pct ← (R−E)/((R−E)+P) × 100`; EQ-02 `recycled_content_pct ← A/P × 100`; EQ-03 `reduced_resource_use_pct ← (I−N)/I × 100`. All three outputs CONS=["DIN-14021-06"]. Transcript confirms EQ-01 and EQ-03 verbatim (l.1302, l.1570).
Missing derived: `general_requirements_met`, `specific_requirements_met`, `verification_requirements_met` (-06) are described as "Aggregat" but hand-typed; `compliance_verdict` likewise.
Re-typed duplicates: none within the standard except the three aggregate booleans; cross-standard: `recycled_content_pct` (product) vs ISO-59020 `pct_RECI_X` (inflow recycled content "qualifies per ISO 14021"); `renewable_material_pct` vs ISO-59020 `pct_RENI_X`; `carbon_footprint_value` is product-level (ISO/TS 14067) and is NOT the same quantity as VSME organisation GHG totals — do not merge.

## 5. Summary
Counts: table-lookups 0 numeric (1 classification: claim type → clause) / repeatable groups 4 (0 wired; dominant: claims register) / conditionals 12 (0 correctly conditional; 18 greedy blocks) / equations 3 (+4 missing aggregates).

TOP 5 UX wins:
1. Make `selected_claim_type` drive visibility and gating: show only the -05 numeric fields and fire only the REQ-28…45 block that belongs to the chosen type — today every claim triggers all 18 blocks, so no claim can pass.
2. Claims register (one row per claim on the product) with the type-specific evidence per row, replacing the single-claim assumption across four worksheets.
3. Derive the three "Aggregat" booleans and the compliance_verdict in -06 from the row gates instead of hand-typing them.
4. Add the missing driver "unqualified vs qualified claim" so the 100 % rules (7.14.2/7.15.2) and the comparative-claim block (6.3) become true conditionals.
5. Checklist for the 6.5.3 a)–g) minimum documentation and the 5.3–5.10 general requirements, with `info_documented_min` / `general_requirements_met` derived.
