## 5. Summary
Counts: table-lookups 0 numeric (6 classification enums) / repeatable groups 8 (0 wired; dominant: elementary flows, impact categories) / conditionals 10 (5 encoded in OR-form, 5 not) / equations 1 (+3 missing).

TOP 5 UX wins:
1. Elementary-flow register in -03 (one row per unit process × flow with the seven §5.3.2 attributes) — the single scalar set cannot describe an inventory, and it retires six re-typed scope fields in -02.
2. Impact-category register in -04 with EQ-01 evaluated per row and `water_footprint_profile` derived as the row set.
3. Gate -04 (impact assessment) on `study_type` so an inventory study is not blocked by REQ-12, and gate Annex-A fields on `is_organization_assessment`.
4. Inherit site water volumes from ISO-46001 / VSME B06 for organisation assessments, and a sites register from VSME B01.200 (consolidation across sites).
5. Turn the a)–j) data-quality list and the 6.2 a)–g) third-party-report list into checklists so `data_quality_requirements` / `third_party_report` are derived.

Data-quality gaps: the only transcript is a Spanish IDT adoption — SR-1 verification of enum labels needs the English source; REQ-21 is `cond=TRUE`; `characterization_factor`, `lci_result`, `category_indicator_result` have unit "-" although dimensioned; VR strings use "IMPLIES" pseudo-logic not supported by the condition grammar; `water_quantities` etc. typed as text where the -03 enums exist.
