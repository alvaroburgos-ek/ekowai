## 5. Summary
Counts: table-lookups 1 classification (Table 3) + 0 numeric / repeatable groups 9 (0 wired; dominant: per-flow X rows) / conditionals 9 (2 encoded as blocks) / equations 13 (+2 missing).

TOP 5 UX wins:
1. Make inflows and outflows repeatable rows (one per flow X) with A.1–A.7 evaluated per row and the linear share derived — the single-X worksheets cannot hold a real system; this is the whole method.
2. Indicator register from Table 3 (13 rows, mandatory flag pre-filled) with selected/applicable/justification per row → derives `mandatory_core_indicators_included` and gates the energy/water/economic blocks (CR-020…025) by selection.
3. Derive `pct_linear_inflow` / `pct_linear_outflow` instead of typing them and then checking the 100 % sum (CR-014/019).
4. Inherit water volumes (VAIW/VTWW/VTWU) from ISO-46001 / VSME B06 and recycled-content facts from DIN-14021 where the same project carries them.
5. Elementary-component/data-source register (§7.6.1.2, §7.6.2) replacing four booleans with rows that carry data_category and traceability.

Data-quality gaps: `aggregation_method` free text although §7.5/Annex G is normative; CR-008, CR-010, CR-036, CR-037 empty conditions; unit "-" on enums; A.3 formula string uses "PRENI(X)" while A.1/A.2 use pct_ symbols (cosmetic); Table 3 "continued" rows (A.5.4, A.6.2, A.6.3) not re-verified verbatim here.
