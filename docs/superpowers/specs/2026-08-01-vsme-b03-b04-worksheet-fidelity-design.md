# VSME B03/B04 worksheet fidelity — design

Date: 2026-08-01 · Owner: Alvaro · Status: approved in-session (design presented and ratified in chat before implementation)

## Problem

1. **B04.100 under-represents the standard.** VSME para 32 requires disclosing "the pollutants it
   emits to air, water and soil in its own operations, **with the respective amount for each
   pollutant**". The EFRAG XBRL taxonomy models this as a hypercube (`AmountOfEmissionsTable` ×
   `TypeOfPollutantAxis`, 94 E-PRTR members). Our importer drops dimensional concepts, so the app
   collapsed this into three aggregate scalars (`AmountOfEmissionToAir/Water/Soil`) that cannot
   carry the per-pollutant breakdown. Compliance-fidelity gap, not just UX.
2. **B03.200 hides its derivation.** `GrossScope1…`, `GrossLocationBasedScope2…` and
   `TotalGrossLocationBasedScope1AndScope2GHGEmissions` are written by the CO₂ engine
   (`recomputeB3Co2`, `source_type='computed'`, per-line UBA citations) but render as ordinary
   editable inputs — inviting double entry and violating the single-source derivation invariant.

## Design

### B04: per-pollutant register (surface_inventory pattern)

- **Carrier field** `pollutant_register` (`data_type='json'`) on worksheet `VSME-B04.100`,
  seeded by SQL migration (precedent: `20260626140000_a138_area_singlesource.sql`), stable UUID,
  `is_required=false`, section = section of `AmountOfEmissionToAir`.
- **Carrier shape** `{ not_applicable: boolean, rows: PollutantRow[] }`,
  `PollutantRow = { id, label, pollutant: string|null, medium: 'air'|'water'|'soil'|null, amount_t: number|null }`.
  `label` is the free-text source description ("what is counted" — installation/process).
  `pollutant` is a taxonomy member name from the E-PRTR list (selection widget, never free text —
  owner ruling 2026-08-01). `not_applicable=true` = explicit "no pollutants subject to reporting"
  (typical small client), which yields 0 sums; an empty register without the flag yields null
  ("fehlend").
- **Shared lib** `src/lib/eval/pollutant-register.ts`: normalizer (single parse path for editor +
  server), `newPollutantRow`, `pollutantRowComplete`, `summarizePollutants` (per-medium sums over
  complete rows). Unit-tested.
- **Pollutant list** `src/lib/vsme/pollutants.ts`, GENERATED by
  `scripts/vsme/extract-pollutants.ts` from the EFRAG VSME XBRL taxonomy 2026-02-01
  (`vsme-definition.xml` domain-member arcs under `TypeOfPollutantAxis`; labels from
  `vsme-label-en.xml` + `vsme-label-de.xml`). Provenance header in the generated file. This is the
  verbatim-source for the member list (taxonomy = EFRAG-published artifact, SR-1 satisfied).
- **Editor** `src/components/worksheet/pollutant-register-editor.tsx` modeled on
  `surface-inventory-editor.tsx`: rows (Bezeichnung/Quelle · Schadstoff dropdown · Medium
  Luft/Wasser/Boden · Menge t), footer with per-medium sums, N/A checkbox. Dispatched in
  `worksheet-form.tsx` (like `surfaceInventoryField`); carrier skipped in the field grid (like
  `rainfall_table_ref`).
- **Write-back**: in `saveWorksheet`'s transaction, mirror the `surfacePresence` block — when the
  batch contains `pollutant_register` for this template, upsert
  `AmountOfEmissionToAir/Water/Soil` as `source_type='derived'` rows and push them into
  `writtenDerived` for client apply. The three scalars remain the XBRL-taxonomy-faithful facts;
  they become derived sums of the register (single producer). No materialize-registry entry:
  producer == consumer, in-batch check suffices (surface precedent; the registry's producer-fire
  path for this shape is not implemented anyway).

### B03 (+ B04 scalars): lock server-derived values

- Worksheet page (server) threads `serverComputedFieldIds` to `WorksheetForm`: field ids whose
  `project_parameters.source_type = 'computed'` (today: only the CO₂ engine writes this), plus —
  scoped to `standardCode === 'VSME'` — `source_type = 'derived'` (the new B04 sums). VSME-only
  scoping for 'derived' avoids touching DWA-A-138 behavior.
- `WorksheetForm` feeds these into `DynamicField isComputed` (existing read-only path) and passes a
  new optional `computedHint { label, href? }`: B03 fields link to the CO₂ activity table
  (`…/vsme/emissions`), B04 scalars point at the register on the same page.
- Market-based Scope 2 and Scope 3 stay hand-entered (voluntary per para 109 / para 52) — they are
  `source_type='manual'` and never lock.

## Error handling

- Incomplete rows (missing pollutant/medium/amount) are excluded from sums; footer shows
  complete/total count (surface-editor convention).
- Unknown/legacy carrier shapes normalize to `{ not_applicable: false, rows: [] }`.
- Migration raises if standard/worksheet/section not found (precedent style); idempotent
  `ON CONFLICT (worksheet_template_id, symbol) DO UPDATE … active=true`.

## Testing

- Unit: pollutant-register normalize/summarize (incl. N/A, incomplete rows, legacy shapes).
- Unit: extractor output sanity is enforced by the generated file being checked in + a test
  asserting list integrity (non-empty, unique values, labels present).
- Component: editor renders rows, N/A state, sums (pattern: existing engine-wiring tests).
- Existing suite must stay green.

## Out of scope

- Report/snapshot rendering of the register (follow-up; scalars keep feeding reports).
- Prod DB apply + deploy: migration is written-not-applied; cutover per deploy playbook after
  owner review.
- Scope-3 category breakdown (only relevant if the Comprehensive module is ever reported).
